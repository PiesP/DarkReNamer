# DarkReNamer

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md)

DarkReNamer는 [DarkNamer](https://github.com/nanpuhaha/DarkNamer)의 비공식
커뮤니티 유지보수 Rust 포트이자 GitHub 포크입니다. DarkNamer 08.02.10의 이름
변환 및 명령 동작을 호환 대상으로 삼지만, 자체 안전 모델과 인터페이스를
사용합니다. `darkwalker`, 서장원 또는 원본 저장소 관리자의 공식 릴리스가
아닙니다.

프로그램은 네이티브 한국어 Windows 인터페이스를 제공합니다. 이 README의
영어·일본어 번역은 프로그램이 해당 인터페이스 언어를 추가로 지원한다는 뜻이
아닙니다.

## 다운로드

[GitHub Releases](https://github.com/PiesP/DarkReNamer/releases)에서 최신 포터블
프리릴리스와 체크섬을 받으세요. 실행 파일은 설치 과정이 필요 없는
`DarkReNamer.exe` 하나입니다. 현재 빌드는 서명되지 않았습니다. 릴리스를
사용하기 전에 [배포 정책 — 영어](DISTRIBUTION.md#current-unsigned-handoff)을
읽고 제공된 체크섬과 출처 증명을 확인하세요.

소스는 [DarkReNamer 저장소](https://github.com/PiesP/DarkReNamer)에서
관리합니다. 직접 빌드하려면 [개발 안내 — 영어](DEVELOPMENT.md)를 따르세요.

## 지원 환경

DarkReNamer는 Windows 11 이상 x64를 공식 지원합니다. Windows 10에서도 실행될
수 있지만 테스트하지 않으며 공식 지원하지 않습니다.

v0.1 파일 시스템 지원 범위는 재분석 지점을 통과하지 않는 대소문자 비구분
로컬 NTFS 디렉터리에서 비관리자 권한으로 실행하는 경우입니다.

| 작업 | 지원 범위 |
| --- | --- |
| 파일 및 디렉터리 이름 변경 | 같은 부모 디렉터리 안 |
| 파일 이동 | 일반 파일만, 같은 로컬 NTFS 볼륨에 이미 존재하는 디렉터리로 이동 |

네트워크 및 장치 경로, NTFS 외 파일 시스템, 대소문자 구분 디렉터리, 관리자
권한 실행, 재분석 지점 통과, 볼륨 간 이동, 디렉터리 이동, 대상 디렉터리 생성,
기존 대상 교체 및 폴더 병합은 지원하지 않습니다. 런타임은 이 범위를 확인하고
조건이 맞지 않으면 안전하게 중단합니다.

## 빠른 사용법

1. 관리자 권한 없이 `DarkReNamer.exe`를 실행합니다.
2. **파일 추가...**를 선택하고 지원 범위 안의 항목을 추가합니다.
3. 이름 변환을 선택한 뒤 제안 이름과 상태 열을 모두 확인합니다. 차단된 행은
   **보기 > 선택 항목 진단...**에서 원인을 확인할 수 있습니다.
4. **변경 적용**을 선택하고 새로 검증된 계획을 확인한 뒤 승인합니다. 확인
   창을 취소하면 파일은 변경되지 않습니다.

지원 범위 안에서 일반 파일을 이동하려면 먼저 **편집 > 대상 폴더 > 모든
파일의 대상 폴더 지정...**을 사용하세요.

## 안전과 복구

- Safe v2는 실행 직전에 항목과 부모의 식별자를 다시 확인하고, 변경 전에
  내구성 있는 Intent를 기록하며, 기존 대상을 교체하지 않는 작업만 수행합니다.
- 미리보기는 현재 제안을 보여줄 뿐입니다. Apply 검증 전에는 실제 파일
  시스템을 검증하거나 변경을 승인하지 않습니다.
- **편집 > 모든 이름 변경 취소**는 제안 이름만 초기화합니다. 디스크에서 이미
  수행된 변경을 되돌리지 않습니다. 대상 폴더 초기화도 제안만 변경합니다.
- 작업이 중단되거나 저널 상태가 불확실하면 이후 Apply가 잠길 수 있습니다.
  저널 증거를 보존하고 시작 시 복구 창을 따르세요. 저널 파일을 옮기거나
  삭제하여 잠금을 우회하지 마세요.

전체 변경·복구 계약은 [안전 모델 — 영어](SAFETY.md)에 있습니다. 외관, 로컬
설정, 진단 및 복구 사용법은 [사용자 안내 — 영어](docs/USER-GUIDE.md)를
참조하세요.

## 검증 범위의 한계

릴리스 검증은 정확한 후보 실행 파일에 자동 소스 검사와 고정 Windows VM
프로필을 결합하는 [VM-Automated 계약 — 영어](SAFETY.md#vm-automated-release-validation)으로
정의됩니다. 정책 문서 자체는 특정 캠페인의 통과를 증명하지 않으며, 이
README도 VM 캠페인 통과를 주장하지 않습니다.

VM-Automated v1은 실제 장치 성능, 물리적 전원 손실, VM 재설정 또는 저장 장치
오류, 사람의 시각 검토 또는 포괄적인 보조 기술 검증, 실제 IME 및 Explorer
드래그 앤 드롭을 다루지 않습니다. DarkNamer와 수동으로 검증한 런타임 동등성도
입증하지 않습니다. 과거 수동·물리적 검증 요구 사항은
[Windows 검증 이력 — 영어](docs/history/WINDOWS-ACCEPTANCE.md)에 별도로
보존합니다.
